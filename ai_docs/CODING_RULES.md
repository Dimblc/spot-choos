# CODING_RULES — Spot & Choo's

## Общие правила
1. Минимальные изменения.
2. Поддерживать чистую структуру.
3. Код должен быть понятным и поддерживаемым.
4. Комментарии — по необходимости, не избыточно.
5. Не дублировать логику.
6. Не добавлять код, не обсудив архитектуру (критические изменения).

## Стиль
- TypeScript: строгий режим (`strict: true`), явные типы для пропсов и публичных функций.
- Tailwind v4: используем `@import "tailwindcss"` и `@theme` для кастомных переменных.
- Размеры типографики и отступов предпочтительно в `vw` для десктопа, но обязательно добавлять мобильные breakpoints (`max-md:`) и `min-*` для доступности.
- Цвета и шрифты задаются через CSS-переменные в `@theme` и `globals.css`.

## AI-специфичные правила
- Перед изменениями читать `AI_INDEX.md` и `OPEN_TASKS.md`.
- Новые решения фиксировать в `DECISIONS.md`.
- Изменения в `CHANGELOG_AI.md`.
- Не коммитить без разрешения пользователя.
- При изменении внешних интеграций (Google Forms, внешние CDN) обновлять конфигурацию в `src/lib/data.ts` и документацию в `ai_docs/`.

## Компоненты
- Server Components по умолчанию; `"use client"` только для интерактива и анимаций.
- Клиентские анимации изолировать в `components/animations/` или `components/providers/`.
- Для GSAP использовать `gsap.context()` и `ctx.revert()` в `useEffect` для очистки.
- Учитывать `prefers-reduced-motion` для всех анимаций.
